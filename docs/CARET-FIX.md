# 手动覆盖光标装饰层说明

## 问题原因

Visual Studio 编辑器的 `CaretAdornmentLayer` 会读取 `Plain Text`、`Caret (Primary)` 和 `Caret (Secondary)` 等格式。`Caret.OnRender` 在**单光标**场景下使用正文画刷，后两项主要用于多光标场景，因此旧版本写入的 `Caret` / `Overwrite Caret` 格式键无法可靠改变当前单光标的显示颜色。

这一行为可以通过只读检查 Visual Studio 编辑器程序集中的相关实现确认。直接把 `Plain Text` 改为红色也不可取，因为这会同时影响代码文字。

## 解决方案

0.1.1 起，扩展采用独立的 WPF 光标装饰层处理手动覆盖状态：

1. 导出独立的 `SmartInput.ManualCaret` 装饰层，位于原生光标层上方。
2. 仅在手动覆盖且当前视图可绘制时，将自定义颜色矩形放到公开 `ITextCaret` 接口报告的坐标和尺寸。
3. 装饰成功添加后才通过 `ITextCaret.IsHidden` 暂时隐藏原生光标，不写入主题或正文颜色。
4. 退出覆盖、失焦、存在选区、离开视口或关闭文档时移除装饰并恢复原生光标。添加失败时不隐藏原生光标；运行异常时回退到原生显示。
5. 根据系统的光标闪烁时间绘制，重复的输入态轮询不会重置闪烁节奏。

扩展运行时只调用公开的 VS/WPF 接口，不使用反射访问 VS 私有字段，也不修改 VS 安装目录。输入法识别与切换状态机不依赖这层显示实现。

## 验证结果

- 0.2.0 Release 构建通过，104 项自动化测试通过。
- 光标测试覆盖绘制控制、位置、恢复、异常、多视图隔离和生命周期清理。
- 离屏 `RenderTargetBitmap` 像素检查确认绘制颜色符合预期。
- Windows 10、Windows 11、Visual Studio 2022、Visual Studio 2026 x64 的实机验证已通过，包含主题切换、DPI、覆盖模式、失焦、多视图和快速切换场景。

离屏渲染和模拟宿主测试不能替代所有 Visual Studio 版本及显示缩放组合的实机验证；后续版本可按 `MANUAL-TESTS.md` 继续回归。

## 实机验证建议

1. 安装 Release VSIX 后打开 C/C++ 或 C# 文件。
2. 在注释中使用输入法实际配置的中英文切换键切到英文，确认光标显示设置的覆盖颜色且代码文字颜色不变。
3. 输入 TODO 并在同一注释内移动，确认手动选择保持，不被自动规则立即抢回。
4. 切回中文、移动到代码区域、点击暂停、切换文档或关闭文档，确认恢复原生光标，不遗留装饰层。
5. 检查横向/纵向滚动、100%/200% 缩放、覆盖模式、主题切换和多视图，不应出现位置偏移、双光标或光标消失。

**不固定要求使用 Shift。** 扩展依据实际输入态变化响应；切换键由输入法设置决定。
